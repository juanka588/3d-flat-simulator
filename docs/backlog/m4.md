# M4 — MCP server v1: read the flat, change it, see it

Refined by the PO/tech-lead agent (2026-10-27) against d03cc89. Size: S ≤ ½ d, M 1–2 d, L 3–5 d. Layers: Vitest, PW, Manual, LLM (needs `ANTHROPIC_API_KEY`).

## User decisions (2026-10-27)
- **Undo: shared stack.** The MCP `undo` reverts the latest change whoever made it (no LLM-only scoping, no `not_llm_entry`).
- **Renderer:** headless Chromium + SwiftShader by default; `FLAT_RENDER_CHANNEL=chrome` opt-in for GPU quality.
- **Apply live**, `preview: true` optional (diff + render, nothing committed). Click-to-approve review mode deferred to M5.
- Public Pages site stays local-only; the MCP/server path is local/dev.

## Decisions
1. **Topology:** separate `apps/mcp` process → `apps/server` over REST (WS only in HTTP mode for resource updates). MCP is a thin adapter: tool call → `CommandEnvelope{author:{kind:'llm', name: clientInfo.name}}` → `POST /api/commands`. Server unreachable → `server_unreachable` tool error with hint. Playwright imported lazily.
2. **Transports:** stdio default (`pnpm mcp`); streamable HTTP `127.0.0.1:8788/mcp` (`--http`, stateless, Host/Origin validation, refuses non-loopback without `FLAT_TOKEN`).
3. **Auth:** reuse `FLAT_TOKEN` (bearer to `apps/server` and on HTTP transport); stdio trusts the parent process.
4. **SDK:** `@modelcontextprotocol/server` v2 (+ `@modelcontextprotocol/client` for tests), v1 `@modelcontextprotocol/sdk` 1.32 fallback — decided by the M4.1 spike. Register raw JSON schemas from `commandToolSchemas()`; `toolCallToCommand` + `parseCommand` stay the single source of validation errors. Images as `{type:'image', data, mimeType}`; failures `isError: true` + `structuredContent`.
5. **Data-driven tool registry:** 13 command tools + read/view/history/render tools; write tools gain `preview?` and `render?`. M5 item commands appear automatically. Snapshot of the full tool list is the contract.
6. **Rendering:** warm headless page in local mode (not a sync client): fetch `GET /api/scene` (reload only when `(epoch, rev)` changes) → `setCamera`/`setLighting` → `whenRendered` → `capture`. Render = f(Scene@rev, ViewState, size). Viewer served by `apps/mcp` from `apps/web/dist` with `?test`; walk-comfort lighting disabled for renders. Budgets: cold ≤ 8 s p95, warm p50 ≤ 1.5 s, hard timeout 20 s; default 1024×768 PNG, long edge ≤ 1568.
7. **Per-call view:** `CameraPose` (orbit/walk/top) in `view.ts` with pure presets (`roomOverviewPose`, `walkPoseInRoom`, `topPose`); `set_sun_time` sets the MCP session view; optional `sync_to_user_tab` relays an ephemeral WS `view` message the tab applies only when "Follow assistant view" is on.
8. **Safety:** structural rules already in the reducer; MCP limits (batch ≤ 50, 30 writes/min, 10 renders/min, 256 KB args); `FLAT_MCP_READONLY`, tool allow-list; scene strings treated as untrusted data.
9. **Author & idempotency:** one ULID per tool call (retry-safe); batch label = the LLM's plan text.
10. **Errors:** reducer codes + `server_unreachable | stale_scene | rate_limited | batch_too_large | read_only | render_unavailable | render_timeout | unknown_room`, each with a "what to call next" hint.

## Demo
1. `pnpm build && pnpm dev:all`; tab shows "Connected"; `claude mcp add flat -- pnpm --silent --dir "$PWD" mcp`.
2. "What rooms does the flat have, and how much sun does the séjour get in winter?" → `list_rooms`, `describe_room`.
3. "Paint the séjour walls sage green and set warm 2700 K evening lighting. Show me before you apply." → batch `preview` + render; tab unchanged.
4. "Apply it and show me." → live change in the tab, one history entry, `render_view` walk view.
5. "Remove the wall between the séjour and the hall." → refused (structural / not supported).
6. "Undo that." → reverts.
7. `ANTHROPIC_API_KEY=... pnpm mcp:demo` automated twin.
