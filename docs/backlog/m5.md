# M5 — Assets & furniture (strategy, 2026-10-27)

Goal: the automatic designer only places **real, purchasable products** — never invented furniture.

## Product-grounded design
- Every placed item references a **product record**: provider, SKU, name, price, currency, URL, exact dims (w/d/h), category, style tags, photo URL.
- Its 3D shape is resolved in order: (1) the provider's real model **streamed through the user's local scene server** for personal viewing (memory-cached, never committed or served from Pages); (2) a CC0 lookalike from our library scaled to the exact dims; (3) a parametric shape at exact dims.
- The LLM can only place items returned by `search_products` / `search_assets` (no free-form furniture).

## Routes (user decisions)
| Route | Decision |
|---|---|
| A. Parametric furniture (kitchen modules, wardrobes/placards, shelves, beds, tables, sofas) | **Yes — core** |
| B. CC0 open library (Poly Haven models, Kenney, Quaternius, filtered Objaverse CC0/CC-BY) | **Yes** |
| C. 3D-FUTURE (research-only, high quality) | **Yes, local-only** download into a gitignored folder (user accepts licence) |
| D. Retailers (IKEA, Leroy Merlin, Maisons du Monde, Castorama, …) | **Spike first** (M5.0): what each exposes (product data, prices, dims, 3D), terms of use, official channels (affiliate feeds, BIM/manufacturer libraries). User decides per provider before connectors are built; connectors run only via the local server. |
| E. Import own scans (GLB/USDZ) | Later (user has no LiDAR; photogrammetry apps still possible) |
| F. RoomPlan | Not applicable (no LiDAR) |
| G. AI image-to-3D | M7 (inspiration images) |

Budget (M9) comes directly from product records.
