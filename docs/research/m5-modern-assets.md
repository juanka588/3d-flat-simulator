# M5 research: modern-style assets for a realistic upgrade plan (2026-10-27)

Status: research only. No repo files other than this document were changed, nothing was committed, no model file was downloaded (thumbnails only, kept in `/tmp/modern-assets/thumbs/`). Scratch data (searches, thumbnails, the contact sheet and the scripts that built this page) is in `/tmp/modern-assets/`.

Problem (user): the catalog lacks kitchen islands, bar stools, TV slat wall panels and, more generally, modern pieces, so the scene looks like a video game instead of a realistic house-upgrade plan.

## 1. Summary

- **74 items** in 8 groups define a "modern French flat" kit (section 3). Each has dims, mount and finish.
- **Free realistic candidate (rating >= 3) exists for 60 of 74**, but for only **38** is it the best primary route. The other 36 are better served by a parametric generator with real PBR textures (exact dims matter and free models are rustic/vintage).
- **IKEA FR has a verified 3D model for 10 items** (armchair, coffee table, shelf, sideboard/commode, dining table, dining chair, wardrobe PAX, dresser, vanity, **kitchen island TORNVIKEN**). For the kitchen island it is the only realistic option today: `K01` is "IKEA-only" in the sense that no free island model is usable (the only popular CC-BY hit is a whole kitchen scene).
- **13 items have neither a usable free model nor an IKEA model** and are purely parametric: slat panel, media wall, rug, wall and open shelves, pantry/wall cabinets, shower screen, entry bench, outdoor deck, throw blanket, wall panelling, skirting.
- Poly Haven (the only source we ingest today) is strong on rustic/vintage and weak on contemporary. The gem for a modern look is **already in our library**: `modern_wooden_cabinet` (fluted doors on black legs, 244 cm, 235 KB) is the right TV unit/sideboard. Everything else modern from Poly Haven is a small set (`modern_arm_chair_01`, `mid_century_lounge_chair`, `bar_chair_round_01`, `outdoor_table_chair_set_01`, vases, clock, baskets, pillows, planters).
- The user-approved **3D-FUTURE local pack** (research-only licence, gitignored, `pnpm models:local`) is by far the best modern furniture supply (from memory: about 16k textured furniture models from Chinese retail interiors, sofas, beds, TV cabinets, bar stools, pendant lights). It does not need a licence review for commits because it is never committed. Recommend the user downloads it; not verified here.
- **Models are not the main cause of the video-game look.** In the viewer, item materials are flat colours (`ITEM_MATERIAL_SPECS`), there is no environment map, box edges are razor sharp, and shadows are hard. Section 9 lists the top five rendering changes; 1 and 2 give more visible gain than any single model swap.
- Proposed budgets (section 8): keep `models/` at <= 300 KB / 6 MB, add a lazy **`models-hd/`** tier at <= 2 MB per hero model and <= 60 MB total, with a 512 px -> 1024 px texture LOD swap. GitHub Pages allows 1 GB sites, so in-repo is fine up to about 100 MB; release assets are **not** usable (no CORS, verified).

## 2. Method and caveats

- **Poly Haven**: full API list (`https://api.polyhaven.com/assets?t=models`, 521 models) filtered by categories, then `/info` and `/files` for 80 shortlisted ids (authors, triangles, size of the 1k glTF with textures).
- **Sketchfab**: public search API (`type=models&downloadable=true&license=cc0|by&sort_by=-likeCount` for every item, plus 15 relevance-sorted queries for the hard items). Licence labels come from the API (`license.label`). Search by popularity is noisy (many hits are whole room scenes), so I kept only plausible, single-object, <= 200k-face results. Downloading needs a token, so nothing was fetched.
- **BlenderKit**: public search API with `license:cc_zero` and `is_free:true`. Many CC0 hits are Poly Haven mirrors; real third-party ones are listed. Downloading needs the add-on login. The default BlenderKit "royalty free" licence is **not** acceptable for committing (it forbids redistributing the asset as such), only `cc_zero` assets.
- **Objaverse**: it is a Sketchfab CC-BY/CC0 subset, so the Sketchfab search above covers it for this purpose; the existing pipeline source (per-object `cc0|by`) can ingest the same UIDs. **Quaternius / Kenney**: stylised low-poly, deliberately not used. **Smithsonian** (via Sketchfab, CC0): historical objects at 100-150k faces (e.g. "Side Chair"), no modern furniture. **ambientCG**: no models (textures only, see section 9). Quaternius CC0 furniture packs were not re-checked here.
- **IKEA FR**: 15 live searches through `pnpm providers:probe ikea-fr "<query>"` (one query returned an esbuild error because `packages/scene/src/commands/schema.ts` had unresolved merge markers in the working tree at that moment, so it was retried once; the failed attempt made no network request, so 15 searches were made in total). Each probe performs a search, one product page, and one model GET, with the provider's politeness rules. Log in section 7.
- Ratings are subjective and thumbnail-based; polygon counts for Sketchfab are the search API "faceCount" (about triangles); BlenderKit sizes are the `.blend` upload with full-resolution textures, not what we would ship.
- Licence rule check: every row marked CC0 is CC0 according to the source API; every Sketchfab row marked CC-BY needs a credit line per object in `docs/MODELS-CREDITS.md` (the existing `models:credits` generator already formats this). A model made from a real retailer or manufacturer product (for example the Terma towel radiators, the IKEA-lookalike ÅRSTID copies on BlenderKit) is licensed by its uploader, but the product design may still carry design/trademark rights; for a personal research repo this is low risk, and it is listed so the user can decide.

## 5. Style definition (what "modern" means here)

Warm-contemporary / Japandi: oak veneer (light, straight grain) and fluted or slatted oak; matt-lacquer white, greige and sage fronts; black powder-coated metal (legs, frames, shelf brackets, pendant shades); bouclé, linen and chunky knit in off-white and taupe; travertine, terrazzo and honed quartz worktops; brushed brass accents; opal glass and rattan lighting. Rounded corners (3-10 mm radius) on every piece, handleless or slim-bar handles, 2-3 mm reveals between doors. This is what the "video game" look lacks: the current generators produce sharp boxes in flat colours (`#b98e5f` wood, `#f0eee8` white) with no grain, no bevel, no gap.

## 8. Budget and pipeline implications

### Calibration from the current library

40 models, 3.9 MB total. Poly Haven models are normalised at 512 px WebP, <= 11.8k triangles, 1-3 materials: 50-297 KB each (e.g. `modern_arm_chair_01` is 2.6 MB at 1k source and 149 KB shipped; `modern_wooden_cabinet` 235 KB; `potted_plant_01` 297 KB, simplified from 96k to 11.4k tris). The 300 KB limit is what forces 512 px textures and heavy simplification, which is exactly why sofas and plants look soft.

Estimate for candidates at 1024 px WebP (q80), Meshopt, <= 20-30k tris: geometry 100-250 KB plus 60-150 KB per 1024 map; a 2-3 material model with colour + normal + ORM lands at **0.5-1.5 MB**. Sketchfab/BlenderKit sources are unknown until downloaded; expect the same order.

### Proposed tiers

| Tier | Where | Per model | Tris | Textures | Total cap | Load |
|---|---|---|---|---|---|---|
| S props (today) | `apps/web/public/models/` | <= 300 KB | <= 12k | <= 512 | <= 6 MB (unchanged) | on placement (already lazy) |
| M standard | same folder | <= 800 KB | <= 20k | <= 1024, 2 maps | counts toward a raised total of 12 MB | on placement |
| H hero | new `apps/web/public/models-hd/` + `catalog.hd.json` | <= 2 MB | <= 40k | <= 1024, 3 maps (colour, normal, ORM packed) | <= 60 MB (about 40 heroes at 1.5 MB) | fetched only when an item of that id is first placed; never preloaded; service-worker/HTTP cache |

Pipeline changes (`scripts/models`): a `tier` field per manifest entry selects `BUDGETS`; `normalise.mjs` already has the Meshopt simplifier and `texMax`/`quality` options; add ORM packing and a normal-map WebP/PNG path; a `sketchfab` source (token via env, licence evidence from the API `license` object, per-object credit into `MODELS-CREDITS.md`); keep sha256 pins so rebuilds do not churn git history.

### GitHub Pages limits and distribution

- Pages published site: 1 GB soft limit, 100 GB/month soft bandwidth, deployment 10 min timeout; GitHub rejects any single git file > 100 MB (and warns at 50 MB). I did not re-verify these against the live docs today. 60 MB of `models-hd/` plus 6 MB of S models is far below all of them.
- Git history is the real cost: every re-encode of a 1.5 MB GLB adds 1.5 MB forever. The pins make rebuilds deterministic; avoid format churn.
- **GitHub Release assets: not usable.** Verified: a release download is a 302 to `release-assets.githubusercontent.com` and neither response carries `access-control-allow-origin`, so a browser `fetch` from the Pages origin would fail.
- **CDN options that do send CORS (verified with an `Origin` request header):** `raw.githubusercontent.com` (`access-control-allow-origin: *`, `cache-control: max-age=300`) and `cdn.jsdelivr.net/gh/<user>/<repo>@<tag>/...` (`access-control-allow-origin: *`). If `models-hd/` outgrows about 100 MB, move it to a separate public assets repo and load through jsDelivr pinned to a tag. Not needed at the proposed size.
- 3D-FUTURE and IKEA models stay local-only (existing guards).

### Texture LOD

- GPU memory is the limit, not download size: a 1024^2 RGBA texture with mips is about 5.3 MB, so 40 hero models x 3 maps would hold about 650 MB. Mitigations in order: (1) ship two texture sets in the hero GLB's sibling file: `slug.glb` (512 px, shown immediately and in orbit/top views) and `slug.hd.glb` (1024 px) swapped in when the camera is within about 3 m, the item is selected, or in walk mode; (2) respect `getPerfProfile().low` (stay on 512 px); (3) LRU-evict HD textures beyond a VRAM budget (the existing `model-cache.ts` is LRU); (4) later, KTX2/Basis (UASTC for normals, ETC1S for colour) cuts VRAM 4-8x and download 2-3x but needs the Basis transcoder (about 200 KB wasm) and `toktx` in the build.
- Shell PBR textures (the CC0 material library, currently 1024 px, 3.9 MB for 25 materials) stay as is; item materials reuse the same texture cache.

## 9. Realism beyond models: top five changes

Facts from `apps/web/src/viewer/**`: `NeutralToneMapping` with computed exposure (`LightingRig.tsx`); `<Canvas shadows="percentage" gl={{antialias:true}} dpr={[1, maxDpr]}>` (`FlatCanvas.tsx`), sun shadow map 2048 (1024 on low); lamps cast shadows; an `aoMap` per room (`room-ambient.ts`); **no environment map anywhere** (no `envMap`/`Environment`/PMREM hits); item materials are `MeshStandardMaterial` from `ITEM_MATERIAL_SPECS` with flat `color/roughness/metalness`; the shell materials already do PBR textures with real-scale tiling (`materials.ts`), and generator `MeshData` already carries UVs in metres, so the plumbing for textured furniture exists.

| # | Change | Why it removes the "game" look | Cost | Risk / perf |
|---|---|---|---|---|
| 1 | **PBR textures on parametric furniture** (oak veneer, matt lacquer, black powder-coat, bouclé/linen normal, travertine/terrazzo/quartz worktop, acoustic felt, brushed brass).
